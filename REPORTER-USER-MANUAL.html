What The Reporter System Is

The Reporter system is Highlander Today’s internal newsroom workflow for turning story ideas, tips, interviews, and source material into reviewable reporting work.

Important rule: the system can help organize material, summarize material, and draft from supplied material, but a human still reviews the result before anything becomes a published article.

Public Story Tips

Public users submit story ideas through /report-a-story.

What the form asks for

  • Topic
  • Who Is Involved
  • What Happened
  • Where Did It Happen
  • When Did It Happen
  • Why It Matters
  • Supporting Links
  • Additional Notes
  • Name, email, and phone
Best submissions are concrete. Names, dates, places, links, and why the story matters locally are far more useful than a vague complaint or rumor.

Submitting this form creates a reporter run for internal review. It does not publish an article automatically.

Main Reporter Admin Page

Internal users begin in /admin/reporter.

This page is the main newsroom queue for reviewing and creating reporter runs.

What staff can do here

  • Search and filter runs
  • Create a run manually
  • Review status and assignee
  • Open the interview queue
  • Jump to Source Monitor or Public Intake

Common run statuses

  • NEW: just entered the system
  • NEEDS_REVIEW: needs newsroom shaping
  • SOURCE_PACKET_IN_PROGRESS: material still being assembled
  • READY_FOR_DRAFT: enough material may exist to draft
  • BLOCKED: something important is missing
  • DRAFT_CREATED: at least one draft exists
A reporter run is one reporting job. Think of it as the working folder for one story effort.

Reporter Run Detail Page

Each run opens in /admin/reporter/[id].

This is the main operational page for a single story effort.

What staff see first

  • Run status
  • Assignee
  • Interview count
  • Source count
  • Open blocker count
  • Draft count
  • Agent task count
  • Claim count
Run Readiness is the fastest summary of what the run still needs. It can tell staff whether the run is missing sources, blocked, waiting for interview review, carrying validation issues, or ready for draft.

Run Tabs Explained

Details Interviews Sources Blockers Analysis Drafts Agent

Details

Use this tab to manage the basic story frame: topic, title, subject, status, assignee, request summary, and editor notes.

Interviews

Use this tab when the story needs direct answers from a person. Staff can add interview requests, invite people, copy interview links, reopen requests, review completed sessions, and mark them reviewed.

Better interview setup produces a better interview. Purpose, what must be learned, known context, and sensitivity notes all matter.

Sources

This tab is the source packet. Staff can add notes, links, official documents, transcript excerpts, and assign a reliability level to each source.

Blockers

Use blockers when the story cannot move forward safely or responsibly, for example because corroboration is missing, the timeframe is unclear, or a response is still pending.

Analysis

Generate Analysis creates an internal source-packet summary. It helps staff understand what is already in the packet before moving into drafting.

Drafts

Generate Draft creates an article draft from the source packet. Convert turns that reporter draft into a normal article draft for editing in the article workflow.

Draft generation can be blocked if there are no sources, open blockers, or completed interview sessions that have not been reviewed.

Agent

This tab is for advanced internal review. It includes triage, internal agent tasks, agent traces, and reviewable claims with verification states such as Supported, Needs Corroboration, Disputed, and Rejected.

Interview Experience For The Interviewee

Interview participants open /interviews/[id].

The browser interview is structured. It starts when the participant clicks Start Interview, confirms the language, and then answers one question at a time.

What the participant is asked to do

  • Answer in detail
  • Include names, dates, places, and timeline
  • Separate personal knowledge from secondhand information
  • Say what is still uncertain
After the interview is complete, the participant’s responses are saved for internal newsroom review. Staff can then review the summary, transcript, facts, and any safety flags.

Monitored Sources

The monitored-source tool lives at /admin/reporter/sources.

It helps staff track recurring public-interest sources such as government pages, school pages, public notices, feeds, and other repeating information sources.

Main actions

  • Run Due Sources: manually run sources that are due right now
  • Fetch now: immediately fetch one source
  • Monitored Source: add a new watched source

Health labels

  • Healthy: working normally
  • Failing: latest fetches are breaking
  • Stale: expected updates are not appearing
  • New: recently added and still being proven
  • Paused: intentionally inactive
  • Archived: no longer part of active monitoring

Recommended Workflow

  1. Create or receive a reporter run.
  2. Review and sharpen it in Details.
  3. Add or clean up the source packet in Sources.
  4. Add blockers if anything important is missing.
  5. Create interview requests if direct testimony is needed.
  6. Review completed interviews and mark them reviewed.
  7. Generate Analysis if the packet needs internal summarizing.
  8. Generate a Draft when the run is ready.
  9. Review validation issues and claims.
  10. Convert the best draft into an article draft.
  11. Finish editing in the regular article workflow.

Common Situations

“We received a tip but it is vague.”

Clean up the topic, add a blocker if the story is unclear, and create an interview request if follow-up is needed.

“We have plenty of links but no clear angle.”

Add the materials in Sources, set honest reliability levels, and use Generate Analysis before moving into drafting.

“The interview is done, but the draft should wait.”

Make sure the completed session is reviewed and check whether any blockers or major source gaps remain.

“A source monitor entry is failing.”

Check the latest error message, try Fetch now, verify the URL and format, and pause or archive the source if it is no longer useful.

Important Limits

  • The reporter system does not publish automatically.
  • The interview tool is login-gated and staff-created.
  • The interview tool is not an unrestricted chatbot.
  • Draft generation depends on supplied material.
  • Open blockers and unreviewed interviews can stop drafting.
  • Monitored sources collect inputs. They do not approve publication.

Best Practices

For tip submitters

  • Be specific
  • Include dates and places
  • Include links if you have them
  • Explain why local readers should care

For newsroom staff

  • Keep run titles and topics clear
  • Add source material before drafting
  • Use blockers honestly
  • Review interview output before relying on it
  • Treat claims and validation issues as real checkpoints
The easiest way to think about the Reporter system is this: tips come in, staff shape the run, interviews and sources build the reporting packet, analysis and drafts help the newsroom, and conversion hands the work into the normal article editor.
